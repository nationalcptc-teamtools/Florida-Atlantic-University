# CPTC 2026 — quick runbook

Scripts are **recon-first collectors** (breadth). Exploits stay manual (hydra,
sqlmap, privesc) per `CCDC-command-dictionary.md`.

## Script 1 — recon sweep

```bash
echo y | ./web-recon.sh <ip>
```

The `echo y | answers the scope gate (never auto-run without it). What it does:

1. nmap top-1000 ports with service detect (`-sT` — required in WSL, `-sS` gets NAT-broken)
2. whatweb fingerprint of the web services found
3. classic exposure checks (git/.env/robots/admin paths)
4. ffuf dir-bust of each **web** port (small wordlist)
5. writes `loot/<ip>-MMDD-HHMM/` with everything + a readable `ffuf-summary.txt`
   (generated by `testing/ffuf_pretty.py` — that folder must stay)

**Read these after every run:**

```bash
cd loot/<ip>-*/ && cat ffuf-summary.txt whatweb.txt quick-wins.txt && cd ../..
```

Real example output (Basic Pentesting box, 10.67.182.108):

```
=== ffuf: http://10.67.182.108 ===
  200  /index.html  [158 B]
  301  /development  → /development/        ← doorway on this box

=== ffuf: http://10.67.182.108:8080 ===
  302  /manager       ← Tomcat manager exists, wants auth
  302  /host-manager
```

## Script 2 — vuln probe of ONE input param

Aim it at any URL that **takes input** — a `?param=value`, a search box, anything
from `<form>`/`<input name="...">` in view-source. It mutates the value with SQLi
strings, `/etc/passwd`, `{{7*7}}`, and a reflection marker, and flags anomalies.

```bash
./web-vuln-tests.sh "http://<ip>/page?param=value"
```

Example (local lab app — `testing/start-lab.sh` first, or any real target):
`./web-vuln-tests.sh "http://127.0.0.1:8080/search?q=first"` produced:

```
  [+] SQL-ish error surfaced on q'          ← send ?q=first' got a DB error
  [i] param 'q' is REFLECTED (XSS possible) ← marker came back in response
```

Rules of thumb:

- **Every `[+]` is a lead, not a verdict.** Confirm with one curl by hand.
  (False positives happen — "no such file" matched the SQL-error words once.)
- A **clean pass is still a report line**: "param X tested for
  SQLi/LFI/SSTI/XSS — no anomalies."
- Loot lands in `loot/vuln-tests-HHMM/` — `hits.txt` (always there, even empty),
  `manual-next-steps.txt` (your exploit commands pre-filled with URL/param).
- No `?param=value` in the URL? That's not an error — the script says so and
  tells you to find params (view-source, or ffuf burp-parameter-names.txt).

## Firewall of common failures

| Symptom | Cause / fix |
|---|---|
| target `000`, script exits loudly | box expired (THM panel) or whoami mistyped |
| nmap finds nothing on live target | need `-sT` (already baked in) |
| ffuf .md unreadable | use `ffuf-summary.txt` instead |
| go to `loot` but empty | you ran from the wrong dir — `cd` to cptc2026 |
